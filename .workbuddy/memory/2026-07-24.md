## 二十六、`display vlan brief` 报"采集/落库异常: not enough values to unpack (expected 4, got 3)"
- **根因（返回值个数 bug，与二十五同类）**：`pipeline.run_check_item` 的 Step1 `send_command` 异常分支（旧 line 367）返回 **3 个值** `(None, False, '命令执行失败: ...')`，但 executor 主循环 `result_raw, is_ok, notes, structured = run_check_item(...)` 解包 **4 个值** → 抛 `ValueError: not enough values to unpack (expected 4, got 3)`，被逐项兜底捕获后写成"采集/落库异常: ..."，**把真实"命令执行失败"原因完全掩盖**。
- **为什么是 vlan brief**：该命令在部分化龙设备 `send_command` 真的抛错（疑似 netmiko ReadTimeout——VLAN 表大/慢 或设备对该精确命令支持差异），触发上面那个 3 值返回。
- **修复**：`send_command` except 分支改为返回 4 元组 `return None, False, f'命令执行失败: {e}', None`（补 `None` 作 structured）。顺带 grep 确认 `run_check_item` 其余 return 均为 4 值。
- **修复后行为**：该命令失败时会直接显示真实原因"命令执行失败: <netmiko错误>"，不再被 unpack 错误掩盖；可由真实报错再判断是调大 timeout 还是 `prune_disabled_commands` 裁剪。
- **验证**：`manage.py check` 0 issues；shell 单测 `RaiseConn.send_command` 抛错 → 返回 4 元组且原因前缀为"命令执行失败"。

## 三十二、复查《能力感知分级巡检_实施方案.md》三轴（健壮性/适应性/耦合性）
