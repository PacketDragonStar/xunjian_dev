## 任务：网络巡检系统（xunjian_system1）技术评审

作为资深网络自动化架构师视角，对该 Django 网络巡检项目做了基于源码的全面评审，产出《巡检系统技术评审报告.md》。

### 项目关键事实（供后续会话复用）
- 技术栈：Django 4.2 + netmiko 4.1.2 + paramiko + MySQL；前端 jQuery+Bootstrap。
- 双引擎并存：旧版 `app02/xunjian.py`（netmiko/paramiko，try/except 被注释，靠 `methon/test1.py` 75KB 方法库）+ 新版 `app02/engine/`（pipeline/executor/reporter，插件化注册表设计，更优）。
- 新版引擎亮点：PARSERS/CHECKERS 注册表、`register_checker` 装饰器、ThreadPoolExecutor 并发(min(32,n+4))、差异化 diff 报告、基线对比。
- 多厂商：H3C/华为/Cisco/NX-OS/TAP。

### 主要短板（已写入报告）
- 无任务调度（无 celery/apscheduler）、无告警推送（邮件/钉钉/IM 均未实现）。
- 巡检在 HTTP 请求内同步执行，阻塞 worker，无任务持久化/续跑。
- 安全：设备 SSH 凭证明文入库、SECRET_KEY/DB 密码硬编码 settings.py、DEBUG=True、ALLOWED_HOSTS=['*']、paramiko AutoAddPolicy 不校验主机密钥、new_run_xunjian 加 @csrf_exempt。
- 容错：旧引擎异常被注释；无重试（tenacity 已装未用）；paramiko sleep+recv 采集脆弱。
- 合规：无 TLS、无细粒度 RBAC/审计，不达等保/ISO 基线。

### 综合评分
- 加权总评 5.3/10（≈53/100），等级：不及格（生产/等保视角）；纯功能视角约 7.0。

### 建议优先项
1. 凭证加密 + 环境变量化配置 + 关 DEBUG + 校验主机密钥 + HTTPS。
2. 引入 Celery 调度 + 任务表持久化 + 告警推送。
3. 收敛双引擎到新版、拆分巨型方法库、加重试与超时。
